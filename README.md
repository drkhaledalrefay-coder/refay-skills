## What is a skill?

A **skill** is a small instruction pack that gives an AI agent (Claude, ChatGPT, Codex or others) a new ability it doesn't have out of the box — like directing an animated short film, auditing a codebase, or planning a brand campaign.

Each skill is a folder with one entry point file called `SKILL.md`. You give the folder (or just that file) to your AI, and it follows the instructions inside. No code to install, no API keys, no dependencies — just copy and go.

**Who is this for?** Anyone who uses an AI assistant and wants it to do more specialized work: filmmakers, marketers, developers, vibe coders, content creators. Many of these skills are designed for non-engineers.

## ⚡ How to install a skill

Each skill is a self-contained folder. Pick the method for your AI:

### Claude Code

Copy the skill folder into your skills directory:

```
~/.claude/skills/
```

For example, to use `fleet-orchestrator`, copy the entire `agent-fleet/fleet-orchestrator/` folder there.

### ChatGPT

Open a conversation in ChatGPT and paste the contents of the skill's `SKILL.md` file as context. The model will follow the instructions in that file.

### Codex (OpenAI)

Paste the `SKILL.md` file as context, or point the agent directly at the skill folder.

> **Tip:** Every skill's entry point is the file called `SKILL.md` inside its folder. That single file contains all the instructions the AI needs.

## 📐 Skill standard

Every skill in this repo follows one format: a kebab-case folder whose entry point is `SKILL.md`, with YAML frontmatter ordered `name`, `description`, `author`, `license`, `source`, and optional `references/`, `scripts/`, `templates/` and `assets/` folders.

* **Formal specification:** [docs/SKILL-STANDARD.md](docs/SKILL-STANDARD.md) — the `SKILL.md` schema, description-writing guide and body structure.
* **Contributing:** [CONTRIBUTING.md](CONTRIBUTING.md) — naming rules, the quality checklist, and how to propose a new skill. Issues and PRs are welcome.

## 🧪 Testing and maintenance

**As of 2026-10-30:** This repository has no automated test suite and no CI pipeline. Quality is maintained through:

- The **skill standard** ([docs/SKILL-STANDARD.md](docs/SKILL-STANDARD.md)) — every skill must pass a format and quality checklist before inclusion.
- **Author review** — all skills are written and reviewed by the author.
- **Versioned releases** — changes are tracked in [CHANGELOG.md](CHANGELOG.md) with semantic versioning.

The repository contains 77 tracked files: 62 Markdown files, 3 Python scripts, 3 shell scripts, 2 PowerShell scripts, and 7 other files. Counts come from `git ls-files` and the `living-readme` facts report.
